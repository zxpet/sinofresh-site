## 3. 两个"跟着元素名走"的坑 —— 字节门两次都是 0 FAIL

这是本批最该记住的一段。**换标签名 + 保住 class ≠ 视觉零变化**：class 规则能压过元素规则，但**class 没声明的属性会留在元素规则上**。

| # | 属性 | 来源 | 后果 | 修法 |
|---|---|---|---|---|
| **1** | `font-weight` | `theme.json` 的 `styles.elements.h1.typography.fontWeight = 700` | Hero 标题当场从 700 掉到 400 | `.sf-formula-hero__title` 补 `font-weight: 700` |
| **2** | `color`（**打印媒体**） | `@media print { h1, h2, h3, p, li, td, th { color:#000 !important } }` | 该规则是**唯一**把公式页标题在打印时压成黑的东西；`div` 不再命中 ⇒**白底白字** | 选择器表补 `.sf-formula-hero__title` |

**穷举方法（三处都要过，缺一处就会漏）**：
1. 主题 CSS 里按元素名的选择器 —— `grep -E '^[^{]*\bh1\b[^{]*\{'`：只有 `h1.sf-slide__title`（不命中）与打印块那条；
2. `theme.json` 的 `styles.elements.<tag>` —— `h1` 给 5 个属性，`heading` 给 `fontFamily/fontWeight/lineHeight`；
3. **渲染页内联的 global-styles** —— 4 条含 `h1` 的规则，其中 2 条要求 `.has-background`／`writing-mode`（不命中）。

**逐属性结论**：size／line-height／letter-spacing／color 早已被 class 覆盖（白拿）；`font-family` 未被覆盖，但 `theme.json` 里 **`heading` 与 `body` 是同一个 Inter 字体栈** ⇒ 天然无差（**这条要显式核验，不能假设**）；`font-weight` 见 #1；打印 `color` 见 #2。**除这两处外没有第三处。**

两条都**看不见**于字节门：它按构造比的是渲染文档，**看不到与媒体相关的级联**。

## 6. 方法论教训（已并入 RULES §Q.7 与 playbook 附录 A.12）

1. ⛔⛔ **改标签名＝改计算样式**：必须**逐属性枚举元素规则**（主题 CSS ＋ `theme.json` ＋ 渲染页内联 global-styles **三处**），且**打印／媒体查询的级联要单独查**。
2. ⛔ **"class 不变"不是"视觉不变"的证明**，只是必要条件。
3. ⛔ **插入一行在渲染产物里不是一行**：块分隔符被消费，注释前后的换行数与基线不同 ⇒ 撤销声明时必须**连它后面那个换行一起去掉**，否则 42 页全红且看起来像产品缺陷。
4. ⛔ **声明改动集从提交推导，不手抄**。
5. ⛔ **"全站不得有 X"是危险断言**：站上本来就有 `<aside class="sf-basket-drawer">`（75 页），首跑因此 75 FAIL。正确形态＝**"该元素恰好少一个、别处一个不动"**（逐页计数 ≈ 基线 − 是否带列）。
6. ⛔ **"盒子不许动"也要分类**：容器**装了新东西就该长高**。判据＝**位置与宽度不动、高度的增量必须等于新内容的盒高＋边距**（"差不多一行"不通过）。
7. ⛔ **取整要显式给容差并报出来**：三个取整值推算第四个可能差 1px；给 1px 容差但**把 off-by-one 打印出来**，而不是把它咽掉。
8. ✅ **声明改动集自带"五处各 42 次"的计数断言** —— 撤销逻辑写错会表现为"42 页有差异"，计数断言把它变成"工具坏了"，归因立刻分清。
