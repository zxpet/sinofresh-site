## 0. 本批形状：`mode: symmetric`（第三种方向）

H7a／H7b 是 `insert`（批次改写基线已有的字符串 ⇒ 期望页可以从基线**造**出来），
H7c 是 `delete`（新增内容的**每个字节都是按记录变的** ⇒ 只能把声明区从候选里拿掉，
要求余下部分等于基线）。H7d 两件事同时发生：**从参数列表里删掉 6–7 行**，**在它上方加一整块控件带**。
两侧的增量都是按记录变的，所以**哪一侧都造不出另一侧**。

剩下唯一诚实的做法：**同一个纯函数同时作用在两侧**，要求余下部分逐字节相同 ——
把「基线里那块控件带」（本来就不存在）和「候选里那几行参数」（本来就已删掉）都按声明删掉，
再比。代价与 `delete` 相同，并且**写在 NC13 里而不是藏起来**：被从两侧同时删掉的东西**不在比较范围内**，
所以那块载荷的**内容**由覆盖断言拥有、**形状**由 `scoped` 拥有、**位置**由 `order` 拥有。

`applies: 84`（候选侧）与 `applies_base: 66`（基线侧）**分开声明**：
`symmetric` 用一个数会让「删新增块的函数在基线上什么也没找到」和「删旧行的函数在候选上全找到了」
两件事互相抵消。基线 66 = 42 页里那些**真有**参数行的页 × 各自行数，候选 84 = 42 页的控件带 + 脚本 + 载体。

**本批另外修好了一条会静默变绿的判据**：`insert` 分支上一度残留 `mask(act)`，
而在这个分支上 `act` 就是**变换后的基线** ⇒ 等于拿基线和自己比，候选一个字节都没读。
它失败时是**红**的（不是绿），所以带着它的 H7c 仍然通过（H7c 走 `delete` 分支），
但 H7a／H7b 会**证明不了任何事**。已恢复为 `mask(b)`，并补 **NC16**：
`insert` 方向必须**拒绝**一个未被施加变换的候选，且**接受**一个真实的候选（两半都在，自带数据）。

## 4. 限定证明：**20/20 ＋ NC1–NC7**（`tools/b2d_h7c_confine.py`，`e4c2dd9..712b01f`）

样式表与脚本是以 **URL** 到达页面的：改一条**既有**规则、改一个**既有**分支，
改变的是读者看到的东西，而 75 页字节**一个都不动** —— 主证看不见、覆盖也看不见。
H7d 把这条证明从「只管 style.css」扩到**脚本**，并收紧了 PHP 侧。

| 声明 | 判据 |
|---|---|
| `--ns .sf-fdetail-config` ＋ `--ns body.sf-config-lock` | 新增的 207 行是**一段**连续规则，且**每个打开的选择器**都属于声明的命名空间（30 选择器 / 1 at-rule / 外部 0）|
| `--fn`×4 | `functions.php` 新增的函数集合与声明**相等**（不是包含）—— 一个发生在没有页面经过的路径上的野函数不会移动任何字节 |
| `--js-removed-ok sir…/inquiry.js=…` | 每个 JS 文件里**被删掉的每一行**都必须被声明；且声明必须**被用到**（不许空转）|
| `--allow-file`×3 | diff 只碰声明的文件（主题三件 ＋ 两个脚本 ＋ 批次档）|

**两处判据修正（本批暴露，都已修）**：

1. `--allow-file` 原先是**替换**默认三件而不是**追加**，与它自己的帮助文字相反。
   第一个同时提交了一份文档的批次，就把它自己的主题文件报成「意料之外的文件」——
   一条声明会**静默收窄到一个路径**的检查，等于一条永远不会在它本来要守的文件上失败的检查。已改为追加。
2. 函数**集合相等**比原来的「一段连续块里含有那个符号」更紧，于是当场抓出**两处声明不全**：
   H7d 没声明它改动的两个 JS 文件、H7c 没声明它新增的第二个函数（`…_specs_table_chips`）。
   补齐后两侧都过。**这不是工具坏了，是工具在工作** —— NC7 就是盯着这一条的（塞一个未声明的函数 ⇒ 必须失败）。
3. 另修：`-U0` 下新增行会在任何一处删除处**断开**，所以「新增恰好一段连续块」对 H7c（1 段）成立，
   对 H7d（还要重写一个渲染器）读出 11–12 段。该条已换成函数集合相等 ＋ 一条信息性行。

## 5. 本批修正的一个产品缺陷（已提交，`712b01f`）

**渲染出「Per per bottle」**：20 个 pack 页的提示读成 `Per per bottle`。

根因是**一个字符串被当成两个东西用**：`hint` 既要当选项上方的提示语，又要被邮件侧用
`substr($group['hint'], 4)` **回头切出**单位短语 —— 而 `sinofresh_formula_pack_parts()` 的尾巴
本来就从第一个非数字字符开始（带着介词），所以 `substr(…,4)` **碰巧永远是对的**，
只有从渲染结果读才能看出重复。改成两个字符串：

```php
'hint'        => $pack_tail !== '' ? ucfirst($pack_tail) : 'Choose one or more',
'unit_phrase' => $pack_tail,
```
```php
if ($group['label'] === 'Pack Size' && !empty($group['unit_phrase'])) {
    $rows[$group['label']] .= ' ' . $group['unit_phrase'];
}
```

判为**修复**而不是升级为停机问题：它是本批自己新写的字符串、**不改数据**、**不改方向**、且只有一个正确写法。
覆盖断言现在**点名**这个错（`sf-fdetail-config__hint">Per per ` 必须为 0），
因为「提示有多少条」这种计数**看不见一个重复的词**。
