## 二、实现

- `functions.php`：`sinofresh_form_options_defaults()`（缺省＝表单现值）＋ `sinofresh_form_options_list()` 读取 ＋ `fluentform/rendering_field_data_select` 过滤器（FF 源码 Select.php:31 实证），按字段 name **前缀**匹配（`country_*` 等——FF 追加的 `_5` 序号跨表单不稳定，不能用全等）
- `inc/formula-admin.php`：`register_setting('sf_site_settings', 'sf_form_options')`（白名单三键、逐行 sanitize）＋ `sf_render_form_options_page()`（三个 textarea，每行一项，中文 hint）
- **契约＝empty-means-absent**：列表清空 ⇒ FF 自身存储的选项照常渲染（下拉永远不会被清空）；option 未存 ⇒ 前台字节与现状零差异；**整体回滚＝删一条 option**（P3 已验证逐字节还原）
- 裁决落地：表单专属 select（Sample Quantity / Tour Type / Number of Visitors / Feedback Type）不进；Document Type checkbox 不纳入；Dosage Form 列表独立 textarea 手改（与 8 个剂型页解耦）

## 五、⚠️ 发现一个既有 bug（非本批回归，待裁决）

**前台表单 label 白底白字**：`.ff-el-input--label label` 计算色 `rgb(255,255,255)`，贴在白色表单卡上——访客只看到红色必填星号和输入框，看不到 Company Name / Country 等任何字段名（有 aria-label 兜底，屏幕阅读器不受影响）。取证：**live 与 preflight 计算色一致**（无 preflight 头复测同为白色），HTML 完全一致，H9b 零 CSS 改动 ⇒ 既有问题，大概率是 FF 外观皮肤（皮肤色假设深底）与主题白卡的冲突。**要不要单开一个批次修（FF 表单皮肤设置或主题 CSS 覆盖）？**
