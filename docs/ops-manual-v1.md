# 册 A · 业务人员速查手册

## A0 给谁看 · 能改不能改一览 · 它怎么帮业务

**本册读者**：销售、编辑、市场等**非技术**同事。你只需要会"改内容"，不需要碰代码、插件、设置。

> **它怎么帮你的业务**：按本册学会自助改文字/换图/看询盘后，不用每次等开发，询盘响应从"天"缩到"小时"，客户体验与成交率直接受益；同时避开红线，不会因误操作导致页面崩坏或合规事故。

| 你能做（内容层）            | 你不能做（结构/系统层）                       |
| ------------------- | ---------------------------------- |
| 改页面文字、产品描述          | 改主题代码 / 插件文件                       |
| 换图片（走媒体库）           | 装/删插件                              |
| 新增/编辑配方（按模板填）       | 改 Site Settings 系统项                |
| 看询盘、回复客户            | 直接改数据库                             |
| 在编辑器里"编辑内容"         | **在 Site Editor 里"保存模板"**（见 A3 红线） |
| 用 UpdraftPlus 打内容备份 | 跑门脚本 h9–h19                        |

> ⚠️ 任何"看起来像设置/结构"的改动，先问专职维护，不要自行操作。

## A1 教程：新同事 30 分钟上手

**目标**：独立完成一次"改文字"操作。

1. **登录**：打开公司提供的**自定义登录地址 `/sf-linyi/`**（路径不写在此手册明文，向专职维护索取完整链接）。输入账号密码。
   - *你应该看到*：WordPress 后台左侧菜单（仪表盘、Formulas、Pages、Media、Site Settings…）。
   - ⚠️ 旧地址 `/wp-admin`、`/wp-login.php` 已停用（返回 404 页面）——**不是故障**，是登录加固。
   - （仅 dev 站内测）会先弹浏览器级 Basic 认证框，输管理员发放的 Basic 账号密码；生产站无此框。
2. **找到要改的页面**：左侧 **Pages → All Pages**，搜页面名（如 About），点 **Edit**。
3. **改文字**：在编辑区直接修改文字，像用 Word 一样。
4. **预览**：点 **Preview**（预览）确认无误。
5. **保存**：点 **Update**（更新）。
6. **强制刷新**：浏览器按 `Ctrl+F5`（Mac `Cmd+Shift+R`）看最新效果。

✅ 完成：你已独立改了一次文字。

## A3 红线一页纸 + 常见 5 问

### 红线（违反任一条即可能造成全网事故）

1. ❌ **禁止在 Site Editor 保存模板**（会生成数据库副本盖掉代码，git 拉取失效）。
2. ❌ **禁止装来路不明插件**。
3. ❌ **禁止在生产跑插件批量更新**。
4. ❌ **禁止直接改主题代码 / 数据库**。
5. ❌ **禁止改内容前不备份**（先用 UpdraftPlus 打内容备份）。
6. ❌ **禁止外传/外发客户询盘截图**（PII）。
7. ❌ **禁止对外透露后台登录地址** `/sf-linyi/`。

### 常见 5 问

- **改完没生效？** 强制刷新（`Cmd/Ctrl+Shift+R`）；若改的是 CSS/JS 类，可能是版本号未 bump，报专职维护。
- **图片不显示？** 检查是否走媒体库上传、URL 是否正确、是否缓存。
- **找不到某页？** Pages → All Pages 搜索；剂型页在 Products/Filters 下。
- **表单收不到邮件？** 查 spam；确认收件人 `sales@zxpet.com`；查 FluentSMTP 日志（Tools → Fluent SMTP → Email Logs）。
- **登录不上？** 确认自定义登录地址与账号；连续失败可能被限流，联系专职维护。

### B1.1 访问路径

### B1.2 密码与限流

- WP 密码：登录页 **Lost your password?** → 注册邮箱收重置邮件。

- 限流机制：自研 mu-plugin `zz-sf-login-guard.php`（重置端点）+ 询盘/投票端点按 `CF-Connecting-IP` 限流；Cloudflare 后取真实访客 IP，不会因"一个 CDN 节点"误伤整片访客。

### B1.3 编辑器基础

- Save draft（存后台）/ Preview（登录可见）/ Publish·Update（前台生效）/ Switch to draft（撤回前台）。

## B4 内容编辑总则（可编辑 / 结构固定 + 环境隔离）

**一句话原则**：**内容可编辑，结构固定。**  
文字、图片、参数值、配置器选项 → 你的地盘；布局、模块顺序、区块框架、代码 → 不要碰。

**可编辑**：About/Quality/Services/Factory Tour 正文、Formulas 全字段、Site Settings 文字项、博客、媒体库、Form Options 三个下拉选项文字。  
**不可编辑（固定结构）**：页头/页脚（社交图标除外）、模块排列与区块框架、首页非公司段、8 剂型页模板文字、JSON-LD、任何 PHP/CSS/JS/模板文件。

**编辑前三习惯**：① 备份（UpdraftPlus 内容级）② 预览 ③ 逐字核对（规格/邮箱/电话）。  
**环境隔离（重要）**：结构/设置类改动**必须先 dev 验证 → 审批 → 部署生产**，禁止直接在生产改结构。内容改动可在生产，但遵循红线与备份。  
**为什么结构不能改**：模板挂着样式、图片匹配、JSON-LD、多语言收词、配置器渲染一整套机制，改一个区块顺序可能导致整页崩或 SEO 数据错乱，且不报错、过几天才被发现。

## B6 产品与配方管理（重点）


### B6.1 结构

- CPT：**Formulas**（21 条产品档案，如 `/formulas/joint-support-soft-chews/`）。
- 字段分组：**Basics → Media → 参数区(params) → 包装(packaging) → 正文(detail) → Spec Sheet → FAQ → Configurator Display**。
- 每个输入框下方有**中文灰色提示**（先读提示再填）。**留空＝前台不显示该区块**（empty-means-absent）。

### B6.2 图集上限语义（H18c 实测，勿凭代码推断）

- `$photo_cap=7`（照片帧）＋ `$frame_cap=8`（总帧＝7 照片＋视频）。**帧①占 1 个照片位** ⇒ 自有照片最多 7 张（前提特色图也用自己的图），不设特色图＝6 张；`gallery_ids` 不限个数但只有**前 6 个**上栏；**视频不占照片名额**。
- 帧序：帧①特色图>剂型图；帧②③④＝`sf_formula_frame2/3/4_id` 槽位>车间图（**位置锁定**、陈旧 ID 回落）；三槽顶替 frame2/3/4 且在自有照片之后 ⇒ 三槽路径最多 4 张。
- **Gallery 选择器"整体替换"语义（H19 实测）**：重开选择器不预选，保存覆盖整套（已有 4 张只补选 1 张会存成 1 张）。修复方案：预选＋取值改 `'toggle'`（待实施）。

### B6.3 参数区（Site Settings → Dosage Form Facts）

- 每个剂型一行四项：**MOQ** / **Lead**（交期默认）/ **Certs**（认证）/ **Packaging**。
- 改一处，**该剂型所有产品**参数条同步更新。⚠️ MOQ 改前和销售确认；产品档案 Tier pricing 首档数量＝最小起订量要对得上。

### B6.4 配置器十组（后台多选 → 前端单选）

### B11.2 备份策略（✅ 两节分写，不混）

**① 内容级备份 — UpdraftPlus（编辑人员用）**

- **谁用**：编辑人员（改内容前自助）。
- **场景**：日常改文字 / 换图 / 加产品**前**打一份；出问题恢复单页 / 单产品。
- **安装三铁律（白名单插件，与"禁止装来路不明插件"红线一致）**：
  1. **只从 wordpress.org 官方插件库安装**，不装第三方 / 破解版。
  2. **备份文件必须存到云存储**（远程 SFTP / 云盘），**不放服务器本地**——避免"服务器坏了，备份也跟着没"的同归于尽。
  3. **装完必须跑一次恢复演练**：挑一条测试页恢复，确认备份真能还原，才算装好。
- **日常步骤**：后台 → UpdraftPlus → 立即备份（按需选数据库 / 文件）→ 记时间。
- **恢复**：UpdraftPlus → 现有备份 → 恢复**单个页面 / 产品**（选对应备份集）。
- ⚠️ 改前必打；出问题秒级回退单页。配置（含云存储凭据）由专职维护完成，编辑只管"打备份 / 恢复"。

**② 全站级备份 — 服务器快照 + WP-CLI（专职维护用）**

- **谁用**：专职维护。
- **场景**：重大改动（主题/插件/结构/设置）前。
- **步骤**：① 云控制台打**服务器快照**；② `wp db export` 导出数据库；③ 备份 `/var/www/zxpet-v2` 与 `wp-content/uploads`。
- **恢复**：从快照回滚整站，或 WP-CLI 导入数据库＋覆盖文件。
- ⚠️ 重大变更前必做；**季度恢复演练**（抽查一次恢复可用性）。

## B13 变更管理（审批阈值 / RACI / dev→prod / 变更记录）

> 参照 ITIL 变更管理 + GMP 变更控制（"变更申请—评估—批准—执行—记录—复盘"）。

**审批阈值（二元判定：先判"要不要审批"）**

- ✅ **免审批（编辑自主，册 A 范围）**：改文字、换图（走媒体库）、加/编辑产品（按模板填）、查看询盘。仅内容层改动，不影响结构/系统。
- ⛔ **必须审批**——出现以下任一类，**先申请再动**：
  - **改代码**：主题 / PHP / CSS / JS / 模板文件；
  - **改结构**：区块顺序、布局、模板、模块增减；
  - **改设置**：Site Settings 系统项（联系信息、剂型事实、Form Options、图库、Global FAQ、工厂信息等）；
  - **改数据库**：phpMyAdmin / SQL 手写、批量数据操作。
  - 分级批准：① 系统级（设置/插件增删/主题·结构）→ **专职维护执行 + 管理批准**；② 重大（DNS/CF/服务器/全站改版/数据库结构）→ **老板批准**。
- ⚠️ 拿不准"算不算结构/设置"时，一律按"必须审批"上报，不要自行判断。

**dev→prod 流程**：dev 验证 → 提交变更申请（含理由/影响/回滚）→ 批准 → 部署生产 → 跑门脚本（h9–h19）→ 验证 → 记录。  
**变更记录（"批记录"）**：谁、何时、改了什么、为何、回滚方案 → 存 `docs/change-log.md`。  
**紧急变更**：先止损，24h 内补记录与复盘。

15\. `[推演]` **Shape/Container 只有虚线框没图？** → 图库未传图，传图即自动显示。  
16\. `[推演]` **图片模糊？** → 原图分辨率/压缩过度。

**产品/配方**  
17\. `[推演]` **配置器选项不对/少一组？** → 查：①字段勾选项 ②Configurator Display 是否 Hide ③该剂型本无此组（鱼油无 Color）。  
18\. `[推演]` **Gallery 覆盖丢失？** → "整体替换"语义，重选全部。  
19\. `[推演]` **特色图占照片位？** → 是，帧①占 1 位。  
20\. `[推演]` **参数改了全站变？** → Dosage Form Facts 联动。  
21\. `[推演]` **详情页规格/保证分析不对？** → AAFCO 式数值须来自检测报告，禁估算；Shelf life 四选一。

**表单/询盘**  
22\. `[推演]` **表单收不到邮件？** → Submissions→FluentSMTP 日志→垃圾箱→技术。  
23\. `[推演]` **进垃圾箱？** → 查 SPF/DKIM（由技术核实 DNS 记录）；让客户把 sales@ 加入联系人。  
24\. `[推演]` **客户看到"请稍后再试"？** → IP 限流触发，等几分钟。  
25\. `[推演]` **Entries 看不到？** → 权限/表单名。

**多语言**  
26\. `[推演]` **语言切换器不见了？** → 中文撤下时随 floater 关闭，走 B10 三步启用。

## B18 应急处理

- **网站打不开**：确认范围（自己 vs 全站，手机流量试）→ 全站：截图→联系维护→查云控制台/进程/日志；仅后台打不开＝Basic 问题。
- **被攻击/挂马**：立即通知维护、保留现场、不自行删文件 → 隔离→取证→文件完整性校验(WP 核心/主题 checksum)→清除→修入口→全量改密→核对 SEO 垃圾→重提交复审。
- **数据丢失**：回收站(30天)；整库/整页损坏＝最近库备份＋主题 git 历史；表单记录随库回滚（丢失备份后新提交，需与销售核对补录）。
- **回滚流程**：① 云快照回滚整站；或 ② UpdraftPlus 恢复；或 ③ `wp db import`＋文件覆盖。
