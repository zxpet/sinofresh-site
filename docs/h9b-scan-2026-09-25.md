## 三、技术事实

- **识别键**：字段 name 是 `country_5` / `target_market_10` / `interested_dosage_form_7` 这类带 FF 追加序号的形式——**前缀匹配**（`country_*`），不能用全等。
- **渲染过滤器**（FF 源码实证，`app/Services/FormBuilder/Components/Select.php:31`）：
  `apply_filters('fluentform/rendering_field_data_' . $elementName, $data, $form)`
  ⇒ 挂 `fluentform/rendering_field_data_select` 改 `$data['settings']['advanced_options']` 即可控制渲染选项。checkbox 同型（`..._data_checkbox`）。
- **验证安全性**：FF select 默认不校验提交值是否在列表内（只查 required），渲染层替换安全；entries/CSV 导出存的是提交值。
- **后台落点**：Site Settings 子页体系已成熟（`inc/formula-admin.php`，`register_setting('sf_site_settings', …)` ＋ `add_submenu_page`），新增「Form Options」子页零新模式。
- **既有契约**：empty-means-absent（Site Settings 值空 ⇒ 表单现值兜底，前台行为不变）。

## 四、方案草案（待裁决）

**方案 A（推荐）**：Site Settings → 新子页「Form Options」，三条共享列表各一个 textarea（每行一项）：

- option `sf_form_options`：`dosage_forms` / `countries` / `target_markets` 三个数组
- 渲染端 hook `fluentform/rendering_field_data_select`：按 name 前缀匹配（`country_*` / `target_market_*` / `interested_dosage_form_*`）替换 `advanced_options`；列表空 ⇒ 原样渲染（表单现值兜底）
- **改一处，3-4 个表单同步**；表单内 FF 编辑器仍可改（被覆盖的仅这三类前缀字段）
- 版本 2.10.84 → 2.10.85；新门 `tools/h9b_gate.py`

**方案 B（否决理由）**：逐字段塞进各表单所在页面后台——15 个 select 逐一对应，复制 11 份副本的痛点原样保留。
**方案 C（否决理由）**：让运营直接用 FF 编辑器——本就是现状，无「改一处同步多处」能力。
